# Панель сервера Mac Mini

Веб-панель администрирования домашнего сервера (Ubuntu 24.04, Mac Mini). ТЗ — `~/PANEL_SPEC.md`.

- **Адрес:** `http://192.168.31.112:7575` (дома) или `http://10.10.10.1:7575` (через WireGuard).
- **Доступ** только из `192.168.31.0/24`, `10.10.10.0/24` и localhost. Работают два рубежа:
  - в ufw порт 7575 открыт только для этих сетей;
  - бэкенд сам отклоняет запросы из других сетей и отвечает 403.
- **Вход** по одному паролю. Сессия хранится в cookie (httpOnly, SameSite=Strict) 30 дней. После 5 неудачных попыток за 15 минут вход с этого IP блокируется.

## Устройство

```
/opt/server-panel/
├── frontend/   shadcn-admin (React 19 + Vite + TanStack Router + Tailwind 4), собирается в frontend/dist
├── backend/    Fastify + TypeScript: API /api/* и раздача frontend/dist на одном порту 7575
│   ├── .env    секреты (600, владелец panel) — в git не входит
│   └── src/    collector/ (метрики), system/, services/, network/, routes/
├── data/       SQLite panel.db (750, владелец panel): метрики, устройства, журнал действий, сессии
└── deploy/     systemd-юнит, sudoers, server-panel-helper, docker-socket-proxy, update.sh
```

- Панель **не зависит от nginx**: её не выключает кнопка «остановить nginx».
- **Служба:** `server-panel.service` работает от системного пользователя `panel`, лимиты памяти `MemoryHigh=150M` и `MemoryMax=250M`. В покое занимает около 40 МБ cgroup и около 85 МБ RSS.
- **Коллектор метрик.** Опрос раз в 30 с. Каждый источник (CPU, температура, SMART, qBittorrent, AdGuard, сеть…) обёрнут в свой `try/catch`: если источник недоступен, в интерфейсе будет «нет данных», а не ошибка.
- **Хранение метрик:**
  - сырые данные — 48 ч;
  - средние по 5 мин — 14 дней;
  - средние по часу — 400 дней.
- **Журнал действий** хранится год.

## Права: что и через что

| Что | Как |
|---|---|
| Логи `/var/log`, журнал systemd | группы `adm`, `systemd-journal` |
| `/home/hawk/disk-monitor.log` | ACL: `panel` — проход в `/home/hawk` и чтение файла |
| `/opt/alert_monitor/config.json` (имя бота) | группа `panel`, права 640 |
| Docker | **без группы docker**, только через `docker-socket-proxy` на `127.0.0.1:2375` (GET containers/info/images/version, логи, POST start/stop/restart; create/exec/delete запрещены) |
| SMART, чтение crontab, start/stop/restart 15 служб, размер querylog AdGuard, WP-CLI (от www-data, одна команда) | `/etc/sudoers.d/server-panel` — только конкретные команды |
| Ключи SSH, ufw deny, fail2ban, завершение сессий, ssh stop/start, `wg show`, arp-scan | `/usr/local/sbin/server-panel-helper` (root:root 755) — сам проверяет каждую команду и аргумент |

Исходники sudoers и helper лежат в `deploy/`. Установленные копии должны с ними совпадать:

```bash
sudo cmp /opt/server-panel/deploy/server-panel-helper /usr/local/sbin/server-panel-helper
sudo cmp /opt/server-panel/deploy/sudoers-server-panel /etc/sudoers.d/server-panel
```

## Как запустить, остановить, посмотреть логи

```bash
systemctl status server-panel
sudo systemctl restart server-panel
journalctl -u server-panel -f          # или в самой панели: Система → Логи → «Панель»
```

## Как обновить после правок кода

```bash
/opt/server-panel/deploy/update.sh      # сборка backend + frontend (от hawk)
sudo systemctl restart server-panel     # нужен только при изменениях бэкенда
```

Фронт отдаётся с диска при каждом запросе, поэтому после пересборки он подхватывается без перезапуска.

Если меняли `deploy/sudoers-server-panel` или `deploy/server-panel-helper`, их нужно установить заново:

```bash
sudo visudo -cf /opt/server-panel/deploy/sudoers-server-panel && sudo install -o root -g root -m 440 /opt/server-panel/deploy/sudoers-server-panel /etc/sudoers.d/server-panel
sudo install -o root -g root -m 755 /opt/server-panel/deploy/server-panel-helper /usr/local/sbin/server-panel-helper
```

## Как сменить пароль панели

```bash
sudo -u panel node /opt/server-panel/backend/dist/scripts/set-password.js
sudo systemctl restart server-panel
```

Хэш argon2id записывается в `backend/.env`. Пароль — минимум 10 символов. Уже открытые сессии продолжают действовать. Чтобы завершить их все, остановите службу и удалите строки из таблицы `sessions`, либо просто нажмите «Выйти» на каждом устройстве.

## Секреты (логины сервисов)

```bash
sudo -u panel node /opt/server-panel/backend/dist/scripts/set-secret.js QBT_USER        # и QBT_PASSWORD
sudo -u panel node /opt/server-panel/backend/dist/scripts/set-secret.js ADGUARD_USER    # и ADGUARD_PASSWORD
sudo -u panel node /opt/server-panel/backend/dist/scripts/set-secret.js JELLYFIN_API_KEY
sudo -u panel node /opt/server-panel/backend/dist/scripts/set-secret.js HA_TOKEN         # Home Assistant, страница «Умный дом» (чтение + тумблеры switch/light); HA_URL по умолчанию http://127.0.0.1:8123
sudo systemctl restart server-panel
```

Ввод скрыт, значения хранятся только в `.env`. На фронт секреты никогда не уходят.

## docker-socket-proxy

```bash
cd /opt/server-panel/deploy/docker-socket-proxy && docker compose up -d      # от hawk (он в группе docker)
```

Панель сама этот контейнер не останавливает: без него она потеряет доступ к Docker.

## Иконки сервисов

Иконки из [dashboard-icons](https://github.com/walkxcode/dashboard-icons) лежат в `frontend/public/icons`, в рантайме ничего не качается. Добавить новую иконку: вписать slug в `frontend/scripts/icons.json`, затем выполнить `cd frontend && npm run fetch-icons && npm run build`.

## HTTPS: https://panel.pulsdev.net

Панель за nginx (`deploy/panel-https/`): виртуальный хост `panel.pulsdev.net` на 443 и 9443 (один адрес `https://panel.pulsdev.net:9443` для дома и мира) → `127.0.0.1:7575`, **доступ только из 192.168.31.0/24, 10.10.10.0/24 и 127.0.0.1** (`allow/deny` на уровне server; через проброс 9443 из интернета — 403). Имя резолвится в LAN записью DNS-rewrite в AdGuard (`deploy/exchange/adguard-rewrite.py --domain panel.pulsdev.net`). Сертификат отдельный, DNS-01 тем же хуком, что у api.pulsdev.net; общий deploy-hook перечитывает nginx после продления.

Установка: `sudo deploy/panel-https/install.sh`, проверка: `deploy/panel-https/verify.sh`. Откат: `sudo rm /etc/nginx/sites-enabled/panel.pulsdev.net && sudo nginx -t && sudo systemctl reload nginx` (панель продолжит работать по `http://192.168.31.112:7575`).

Панель верит заголовкам `X-Forwarded-*` только от соединений с 127.0.0.1 (`trustProxy`): в журнале и блокировках настоящий адрес клиента. Cookie сессии получает `Secure`, когда запрос пришёл по HTTPS; вход по `http://` в LAN работает как раньше.

## Ссылки на веб-интерфейсы служб

Адреса qBittorrent, AdGuard, Portainer, Jellyfin, зеркала сайта, Marantz и т. д. не строятся из адреса страницы (панель открывается и по `https://panel.pulsdev.net:9443`, где портов служб нет, а HSTS принудительно меняет http на https). Их отдаёт сервер: `GET /api/links` (реестр `backend/src/services/links.ts`, адрес сервера в LAN — переменная `LAN_HOST` в `backend/.env`, по умолчанию `192.168.31.112`). Схема у каждой службы своя (все отвечают по http, админка SFTPGo — https). Снаружи адреса не отдаются, ссылки неактивны с подсказкой «Доступно только из домашней сети или через WireGuard». Новая служба: строка в реестре и `<HomeLink service='id'>`.

**Ссылка «Обновить» в Telegram.** Сообщения об обновлениях (новые пакеты apt, безопасность, новая версия Docker-образа) заканчиваются ссылкой «Обновить» → `{PANEL_PUBLIC_URL}/updates?focus=apply`. Страница «Обновления» прокручивается к кнопке «Обновить всё» и на пару секунд подсвечивает её; ничего не запускается, установка — только нажатием кнопки. Адрес панели для ссылки — `PANEL_PUBLIC_URL` в `backend/.env` (по умолчанию `http://192.168.31.112:7575`; работает из дома и через WireGuard, для WireGuard-only можно поставить `http://10.10.10.1:7575`); меняется без пересборки, нужен `sudo systemctl restart server-panel`. Если сессии нет, после входа пользователь возвращается на эту же ссылку (параметр `redirect`, принимаются только внутренние пути панели, `//host` и `https://…` отбрасываются).

## Страница «Медиа» (`/media-control`): ресивер, телевизор, пульты

Меню «Сервисы»: **Медиа** (эта страница) и **Медиа-серверы** (прежняя страница Jellyfin/MinimServer/BubbleUPnP, маршрут `/media` не менялся). Отдельного пункта «Ресивер» нет: старый `/receiver` (и `?tab=remote`) и `/media/remote` перенаправляются на `/media-control` с нужной вкладкой. Вкладки (`?tab=`): `receiver` — блоки управления ресивером (как раньше, порядок блоков `layout.receiver`), `tv` — карточка телевизора, `receiver-remote` — пульт RC042SR (раздел ниже), `tv-remote` — пульт Samsung AA59-00602A, `universal` — универсальный пульт (раздел ниже). ⌘K: «Marantz NR1604», «Пульт ресивера», «Телевизор Samsung», «Пульт ТВ», «Универсальный пульт» ведут на свои вкладки.

### Вкладка «Универсальный» (`?tab=universal`)

Своя сетка крупных плиток из частых кнопок обоих устройств и сцен: 2 колонки на телефоне, до 6 на широком экране; вид плиток — как у «Быстрых сцен» (десять цветов, двенадцать значков), нажатие — как у экранных пультов (вдавливание, короткая вибрация, удержание с автоповтором у громкости и стрелок).

- **Состав и порядок** — настройка `universal.remote` (общая для всех устройств), `GET/PUT /api/universal/remote`, `POST /api/universal/remote/reset`; журнал действий `universal.remote`. Кнопка пульта: `{id, source: receiver|tv|scene, command, label, icon, color}`, до 48 штук.
- **Новых способов управления нет.** `command` — это **кнопка уже существующего экранного пульта** (`receiver.remote` / `tv.remote`) или `entity_id` сцены панели; сервер проверяет её по тем же спискам и разворачивает через привязки, а нажатие уходит прежними маршрутами: `/api/receiver/command`, `/api/tv/key`, `/api/smarthome/ha/scene` — со своими белыми списками, лимитами, потолком громкости и журналом. Переназначили команду на оригинальном пульте — поменялась и плитка.
- **Серые плитки** — те же правила, что у оригиналов: кнопка без команды, вход не из живого списка ресивера, выключенный ресивер, ТВ не отвечает или кнопка недоступна через Home Assistant, недоступная сцена. Питание активно всегда (выключенный ТВ поднимает сцена).
- **Набор по умолчанию** (пока настройки пусты): питание ТВ и ресивера, громкость ▲▼ и Mute ресивера, навигация ▲▼◀▶ и OK телевизора, «Назад», «Выход», «Меню ТВ», входы TV / CBL-SAT / Media Player и режимы Movie, Music, Game, Pure Direct.
- **Режим «Изменить»** (переключатель в углу вкладки): плитки перетаскиваются (dnd-kit, те же сенсоры, что у `SortableBlocks`; порядок сохраняется в `universal.remote`, а не в `layout.*`), «⋯» на плитке — подпись, цвет, значок, удалить; «Добавить кнопку» — источник (ресивер, телевизор, сцена) → список с поиском → подпись, цвет, значок; «Сбросить по умолчанию» убирает настройку.

**Телевизор Samsung** (`services/tv.ts`, `services/tvHa.ts`, `routes/tv.ts`; адрес `TV_HOST`, по умолчанию 192.168.31.181; сцена включения `TV_SCENE_ON`, по умолчанию `scene.tv_on`).

**Команды идут через Home Assistant** — настройка `tv.driver`: `ha` (по умолчанию) или `direct` (прямой WebSocket, запасной путь). Причина: UE55TU7090 панели токен не выдаёт (окно «Разрешить» не появляется, на `ms.remote.control` приходит `ms.error`), а интеграция «Samsung Smart TV» в HA уже сопряжена с телевизором и свой токен хранит. Панель к телевизору напрямую в этом режиме не ходит вообще.
- Сущности ищутся сами среди `media_player.*` и `remote.*` по имени (samsung/телевизор/tv); ручная замена — настройки `tv.haRemote` и `tv.haMedia` (entity_id). Что найдено, видно в `GET /api/tv/status` (`entity`) и в скрипте ниже.
- Есть `remote.*` — любой ключ из белого списка уходит как `remote.send_command {entity_id, command: ["KEY_…"]}`, то есть работают все кнопки пульта.
- Нет `remote.*` — остаются только сервисы медиаплеера, и лишь те, что он сам объявил в `supported_features`: `volume_up`, `volume_down`, `volume_mute` (с `is_volume_muted` от текущего состояния), `turn_on`/`turn_off` (питание), `media_play`, `media_pause`, `media_stop`. Цифры, стрелки, меню, источник и каналы в этом случае серые с подсказкой «через Home Assistant недоступно»: отдельных сервисов для них нет, и придумывать их панель не будет.
- Белый список — в `haClient.ts` (`TV_DOMAINS`, `TV_SERVICES`): только домены `media_player` и `remote`, только перечисленные сервисы и только для сущности, чей домен совпадает с вызовом. Ключи — прежний `KEYS` из `tv.ts`. Лимит 5 команд в секунду и журнал действий (кроме громкости и стрелок) общие для обоих режимов.
- Состояние сущности ТВ приходит живыми событиями HA (`haLive`, домены `media_player`/`remote` добавлены в белый список подписки), поэтому карточка обновляется без лишних чтений.
- Список сущностей и то, какие кнопки получатся (только чтение): `sudo -u panel node /opt/server-panel/backend/dist/scripts/list-tv-entities.js` — entity_id, название, состояние, `supported_features` словами, источники, выбранные панелью сущности и перечень серых кнопок.
- `GET /api/tv/status` → `{online, port, paired, tokenAuth, driver, entity, keys, host, sceneOn}`; страница опрашивает раз в 15 с, только пока открыта. Токена в ответе нет. В режиме `ha`: «в сети» — сущность ТВ отвечает и не выключена, «сопряжён» — сущность есть и доступна (в карточке пишется «через Home Assistant»), `keys` — ключи, которые сейчас реально можно отправить (остальные кнопки серые). В режиме `direct`: TCP-проверка 8001/8002 (таймаут 1,5 с) плюс `GET http://ТВ:8001/api/v2/` (кэш 60 с), и «в сети» с «сопряжён» — разные вещи: сокет Tizen открывает кому угодно, а без токена молча игнорирует команды.
- `POST /api/tv/key {key}` — ключ из белого списка (`KEYS`). В режиме `ha` уходит сервисом Home Assistant (см. выше). В режиме `direct` — короткая сессия: WebSocket `wss://ТВ:8002/api/v2/channels/samsung.remote.api.v2?name=<base64>&token=…` (если 8002 недоступен — `ws://…:8001`), команда `{"method":"ms.remote.control","params":{"Cmd":"Click","DataOfCmd":"KEY_…","Option":"false","TypeOfRemote":"SendRemoteKey"}}`. Не больше 5 ключей в секунду (429), ТВ не отвечает — 502 «Телевизор не отвечает в сети», нет сопряжения — 409. В журнал (`tv.key`) пишутся все ключи, кроме громкости и стрелок.
- `POST /api/tv/pair` — только для режима `direct` (в режиме `ha` сопрягать нечего, кнопка «Сопрячь» скрыта): открывает сокет без токена; на экране ТВ нужно нажать «Разрешить» (ожидание 30 с). **Сопряжение засчитывается только если ТВ выдал токен**: Tizen присылает `ms.channel.connect` сразу всем, поэтому открытый сокет ничего не доказывает. После `connect` без токена ждём ещё 10 с (токен приходит, когда владелец нажал «Разрешить»), и если токена так и нет — ошибка с инструкцией по меню телевизора, режим сопряжения не сохраняется. Токен сохраняется зашифрованным (`secretbox`, `tv.token`), наружу не отдаётся; `mask.ts` скрывает `token=…` и `"token":"…"` в ошибках и логах.
- Режим сопряжения — настройка `tv.pairMode`: `token` (обычный путь) или `open` — ТВ без поддержки токенов (`TokenAuthSupport=false` в `/api/v2/`), такие модели принимают ключи и без токена. Пустой токен сопряжением не считается (в том числе остатки первой версии: `tv.paired=true` без токена — панель сама перестаёт считать такой ТВ сопряжённым).
- После отправки ключа сокет держится ещё 0,6 с: ТВ успевает выполнить команду, а если откажет (`ms.error`, `ms.channel.unauthorized`) — панель отдаёт ошибку, а не «ок».
- Питание: если ТВ не отвечает (в режиме `ha` — состояние сущности `off`/`unavailable`), кнопка питания запускает сцену (`POST /api/smarthome/ha/scene`), иначе шлёт `KEY_POWER`. Поэтому питание активно всегда, даже когда остальные кнопки серые.
- Привязки кнопок пульта ТВ — `GET/PUT /api/tv/remote[/:кнопка]`, настройка `tv.remote` (режим «Настроить пульт» как у ресивера; журнал `tv.remote`).
- Проверка, когда ТВ включён (только чтение, ключи не отправляются): `node /opt/server-panel/backend/dist/scripts/probe-tv.js` — порты 8001/8002/55000, `GET :8001/api/v2/` (модель, год, PowerState, TokenAuthSupport); `node /opt/server-panel/backend/dist/scripts/probe-tv-ws.js [8002|8001] [секунды] [apps]` — открывает сокет тем же именем, что и панель, и печатает всё, что присылает ТВ (события, коды закрытия, есть ли `data.token` — значение не печатается); `apps` дополнительно запрашивает список приложений: на этот запрос отвечает только авторизованный канал. ⚠️ При запуске на экране ТВ может появиться окно «Разрешить».
- **Если кнопки «не нажимаются»**: ТВ пускает подключение, но не авторизует его. На телевизоре: Настройки → Общие → Менеджер внешних устройств → Менеджер подключения устройств → включить «Уведомление о доступе», в «Списке устройств» удалить запись панели; затем «Сопрячь» в панели и подтвердить окно на экране. Проверено на UE55TU7090 (Tizen, API 2.0.25, `TokenAuthSupport=true`): без токена ТВ не отвечает даже на чтение списка приложений.

**Ключи «не проверено»** (на этом ТВ не проверялись, в окне выбора помечены): `KEY_CH_LIST`, `KEY_TTX_MIX`, `KEY_CONTENTS`, `KEY_PICTURE_SIZE`, `KEY_AD` — имена из общедоступных таблиц Samsung (список Home Assistant, samsungctl); `KEY_EMANUAL` — имени этой кнопки в таблицах нет вообще, для E-MANUAL пультов серии AA59 там указан `KEY_TOPMENU`. Поэтому в белом списке есть ещё две замены, по умолчанию ни на одной кнопке не стоящие: `KEY_TOPMENU` (вместо `KEY_EMANUAL`) и `KEY_CAPTION` (вторая роль AD/SUBT. — субтитры); если умолчание не сработает, кнопку перевешивают в режиме «Настроить пульт». Остальные — стандартные коды Samsung, но живая отправка на этом телевизоре тоже ещё не выполнялась (ТВ был выключен). Пульт AA59-00602A — старой серии: часть кнопок на новом Tizen-ТВ может не работать.

## Ресивер: вкладка «Пульт ресивера» (страница «Медиа», `/media-control?tab=receiver-remote`)

Экранная копия пульта Marantz RC042SR (`frontend/src/features/receiver/remote-pad.tsx`): тёмный корпус, кнопки с «вдавливанием» и короткой вибрацией на телефоне; на узком экране пульт во всю ширину до 420 px, на широком по центру. Громкость, стрелки меню и Tune ▲▼ повторяются при удержании (интервал 280 мс — в пределах лимита 4 команды/с и потолка `MARANTZ_MAX_VOLUME`, их держит сервер). Всё идёт через `services/receiver.ts` и его белый список; новые команды только из него.

**Привязки кнопок.** Умолчания — `services/receiverRemote.ts` (`REMOTE_DEFAULTS`), отличия от них хранятся на сервере в настройке `receiver.remote` (общая для всех устройств, как `layout.*`). `GET /api/receiver/remote` → `{defaults, bindings, commands}`; `PUT /api/receiver/remote/:кнопка {command}` — команда из белого списка, `null` (кнопка без команды) или `"default"` (вернуть умолчание); журнал `receiver.remote`. Переключатель «Настроить пульт» в углу вкладки: нажатие на кнопку открывает выбор команды с поиском, «Без команды», «По умолчанию». Кнопка без команды, вход, которого нет в живом списке ресивера, и (при выключенном ресивере) всё, кроме питания и зон, — серые и неактивные, в подсказке причина. Под оригинальной подписью входа — реальное имя из ресивера.

**Команды по умолчанию.** Переключатели «по состоянию» — виртуальные команды, сервер читает состояние и сам выбирает команду: `PWTOGGLE` (PWON/PWSTANDBY), `MUTOGGLE`, `ZMTOGGLE` (ZMON/ZMOFF), `Z2TOGGLE`, `MENUTOGGLE` (SETUP: MNMEN ON/OFF, состояние меню помнит сервер), `ECOCYCLE` (ECOON → ECOAUTO → ECOOFF; `ECO?` не отвечает, поэтому помнится последнее принятое), `SLPCYCLE` (SLP010 → 030 → 060 → 090 → 120 → OFF по чтению `SLP?`).

## Умный дом (`/smarthome`)

Устройства Home Assistant берутся из его реестров (токен `HA_TOKEN` в `backend/.env`, адрес `HA_URL`, по умолчанию `http://127.0.0.1:8123`, только локальная сеть) и раскладываются по блокам (комната HA → интеграция → «Прочее»). Ручные устройства (ссылка/HTTP/TCP/ping) работают отдельно.

**Управление.** На карточке устройства с `switch` или `light` есть тумблер (у многоканальных — «название канала + тумблер»). Нажатие сразу меняет тумблер, панель шлёт `POST /api/smarthome/ha/toggle {entity_id, action: on|off}`, а в карточку возвращается реальное состояние из HA (`GET /api/states/<entity_id>`); при ошибке тумблер откатывается и показывается сообщение. Недоступная сущность (`unavailable`) — серый неактивный тумблер. В режиме «Изменить порядок» содержимое карточек заморожено, тумблеры не нажимаются и не мешают перетаскиванию.

**Белый список.** Только домены `switch` и `light` (`CONTROL_DOMAINS` в `backend/src/services/haClient.ts`), только `turn_on`/`turn_off`. Сущность должна быть у синхронизированного, не скрытого и не пропавшего из HA устройства панели, иначе 403. `lock`, `cover`, `climate`, `fan`, сценарии и любые другие сервисы с панели недоступны. Чтобы расширить список — менять домены в коде, это отдельное решение. Лимит: не больше 5 переключений в секунду на всю панель (429). Таймаут вызова HA — 5 с.

**Журнал действий** (`smarthome.ha.toggle`): сущность, название устройства, on/off, прежнее и новое состояние, результат (`ok`/`error`/`denied`). Токен и заголовки не пишутся, ошибки проходят через `mask.ts`.

**Живое обновление состояний.** Панель подписывается на события Home Assistant `state_changed` по WebSocket (`backend/src/services/haLive.ts`) и обновляет тумблеры `switch`/`light` и доступность сцен сразу при событии; остальные сущности игнорируются, токен не логируется. При обрыве — переподключение с нарастающей паузой (1, 2, 4 … до 60 с), а пока связи нет, состояния обновляются обычным опросом HA раз в минуту (после переподключения — сразу полное чтение). Ответ `POST /api/smarthome/ha/toggle` теперь `{entity_id, name, state, confirmed}`: после команды состояние читается из `GET /api/states/<id>`, и если оно ещё не стало ожидаемым (Sonoff LAN подтверждает не сразу), делается до 2 повторных чтений с паузой 700 мс; `confirmed=false` — устройство не подтвердило. Состояние сразу записывается в реестр панели, поэтому следующий `GET /api/smarthome/devices` отдаёт его без ожидания синхронизации. Страница «Умный дом» опрашивает список раз в 3 с, пока открыта и вкладка видна (на скрытой вкладке опрос стоит); ответы опроса, начатые до нажатия тумблера, игнорируются. При `confirmed=false` рядом с тумблером до 3 с крутится индикатор ожидания, затем показывается то, что вернёт опрос; если состояние не совпало — «Устройство не подтвердило».

**Быстрые сцены.** Сцены Home Assistant (`scene.*`) синхронизируются в таблицу `smart_scenes` и показываются плитками вверху страницы (как «Запуск одним касанием» в Smart Life). Новые сцены появляются сами, пропавшие помечаются, а не удаляются; имя, цвет, значок и скрытие владельца синхронизация не затирает. Имя по умолчанию: буквы через пробел склеиваются («O F F» → «OFF»). Порядок плиток — `layout.smarthome-scenes` («Изменить порядок» → «Порядок сцен»). Нажатие: `POST /api/smarthome/ha/scene {entity_id}` → `scene.turn_on`. Настройки плитки: `PATCH /api/smarthome/scenes`. В ⌘K есть «Сцена: <имя>». Список сцен из HA без токена в выводе: `sudo -u panel node /opt/server-panel/backend/dist/scripts/list-scenes.js`.

**Белый список управления:** `switch`/`light` — `turn_on`/`turn_off`; `scene` — только `turn_on`. Сцена должна быть в реестре панели, не скрыта и не пропавшей (иначе 403); `unavailable` — 409; одна и та же сцена не чаще раза в 300 мс и не больше 5 вызовов в секунду на всю панель (429). Журнал: `smarthome.ha.scene` (имя и entity_id сцены, результат). Остальные домены с панели недоступны.

## Обменник файлов (SFTPGo)

**Хранилище.** Данные обменника лежат на hdd1tb: `/mnt/hdd1tb/sftpgo-data`, а `/srv/exchange` — символическая ссылка на них (путь в compose, панели, ссылке SFTPGo шары MacMini и nginx не менялся). Перенос: `sudo deploy/exchange/move-to-hdd1tb.sh`, откат: `sudo deploy/exchange/rollback-hdd1tb.sh`, проверка: `deploy/exchange/verify-hdd1tb.sh`. Если диск не смонтирован, ссылка ведёт в никуда, а в compose `create_host_path: false`, поэтому контейнер не стартует и не пишет на SSD. Сторож `sftpgo-guard.sh` (cron hawk, раз в минуту) останавливает контейнер без диска, запускает его, когда диск вернулся, и перезапускает при привязке к старому монтированию (журнал `~/sftpgo-guard.log`). Статус хранилища виден в карточке «Сайты и API → Обменник». Старая папка после переноса — `/srv/exchange.old`. Доказательство на loop-образе: `sudo deploy/exchange/test-hdd-loop.sh`.

Файлы для людей вне сети. Гости открывают `https://api.pulsdev.net:9443/files/`, из дома — `https://api.pulsdev.net/files/`. Пользователи, папки и права — в **админке** `https://api.pulsdev.net:8443/files/web/admin/`: она открывается только из домашней сети и VPN. Установка — `sudo deploy/exchange/install.sh`, обновление образа — `sudo deploy/exchange/update.sh` (пересобирает и русский перевод веб-клиента). Порты и включённые протоколы задаются в `/opt/sftpgo/compose.yaml`, в веб-интерфейсе их нет.

**Готовые пользователи** (создаёт `~/Scripts/exchange-users.py`): `admin` — весь обменник, квота 25 ГБ (в неё входят и гостевые папки); `uploads` — гость: только список, загрузка и создание папок, квота 20 ГБ. Файл — не больше 10 ГБ. Раз в час SFTPGo пересчитывает занятое место, поэтому квота `admin` учитывает загрузки гостей с задержкой до часа.

**Как добавить нового гостя со своей папкой** (админка, английский интерфейс с русскими подписями «Имя пользователя», «Пароль»):

1. **Users** → у строки `uploads` меню **Действия** → **Use as a template**: форма откроется уже с нужными правами и лимитами. (Можно и **Добавить** с нуля — тогда пройдите пункты 3–6.)
2. Введите **Имя пользователя** (например `ivan`) и **Пароль** — не короче 12 символов.
3. **File system → Root directory**: `/data/exchange/ivan`. Папка создастся сама; `admin` увидит её рядом с `uploads`.
4. **ACLs → Permissions**: оставьте только `list`, `upload`, `create_dirs` (звёздочку `*` и остальное снимите). Скачивание не включайте: под одним логином бывает несколько людей.
5. **ACLs → Denied protocols**: отметьте `SSH`, `FTP`, `DAV` (`HTTP` не отмечайте, иначе вход в веб-клиент закроется). **Web client/REST API**: отметьте `shares-disabled`, `password-change-disabled`, `api-key-auth-change-disabled`, `publickey-change-disabled`, `tls-cert-change-disabled`, `mfa-disabled`, `info-change-disabled`, `password-reset-disabled`.
6. **Disk quota and bandwidth limits**: **Quota size** — например `10GB`, **Max upload size** — `5GB` (суффиксы MB/GB/TB работают).
7. **Сохранить**, затем проверьте вход на `https://api.pulsdev.net:9443/files/`. Пароль передайте человеку лично.

Панель присылает в Telegram сообщение о загрузке любого гостя (все пользователи, кроме `admin`): имя файла, размер и IP. Отключить гостя — Users → **Изменить** → **Профиль** → Status: Inactive. Забаненные за подбор пароля адреса видны в админке (IP Manager → IP Lists) и в `fail2ban-client status exchange`.

## Обновление Docker-контейнеров из панели («Обновления» → «Docker-образы»)

Панель показывает версии «было → станет» для всех восьми контейнеров (метки `org.opencontainers.image.version` образа и реестра,
без pull; нет метки — дата сборки и короткий digest). Кнопка **«Обновить…»** есть только у контейнеров из белого списка помощника.

- **Помощник:** `/usr/local/sbin/server-panel-docker update|rollback <имя> [--dry-run]` (исходник `deploy/server-panel-docker`,
  sudoers `deploy/sudoers-server-panel-docker` — две точные команды). Установка: `sudo deploy/install-docker-helper.sh`.
- **Белый список:** `/etc/server-panel/docker-projects.json` (root:root 644). Контейнер добавляется по одному:
  `sudo deploy/docker/install-project.sh <имя>` (берёт `deploy/docker/<имя>/compose.yaml` + `project.json`, кладёт root-копию в
  `/etc/server-panel/docker/<имя>/` и запоминает её SHA-256; изменённый файл помощник не примет). Убрать: `... --remove <имя>`.
- **Алгоритм update:** flock → проверки и замки → `docker inspect` в JSON + тег `rollback-<ts>` на текущий образ + копии данных →
  `compose pull` (контейнер ещё работает) → если образ не изменился, выход → `up -d --no-deps --pull never` (без down/-v/--remove-orphans;
  контейнер от `docker run` переименовывается и после успеха удаляется) → проверка здоровья (работает, не перезапускается, HTTP/TCP/DNS,
  N секунд подряд) → при провале автооткат на сохранённый образ. Работа идёт в юните `sp-docker-<id>` (systemd-run), панель можно перезапускать.
- **Состояние:** `/var/lib/server-panel-docker/{jobs,state}` (читает panel), `inspect/` и `backups/` — только root. Журнал задачи — `jobs/<id>.log`.
- **Замки:** qBittorrent — незавершённые закачки (проверяет панель) и работающий `move-completed.sh` (проверяет помощник).
  Опасные контейнеры (portainer, adguardhome, qbittorrent, docker-socket-proxy) требуют повторного ввода пароля панели.
- **Параметры проекта** (`deploy/docker/<имя>/project.json`): `backup` (каталоги для копии), `backup_stopped` (копия при остановленном контейнере, сразу
  перед пересозданием — для баз), `backup_required` / `backup_max_gb` / `backup_keep`, `rollback_restore_backup` (откат = образ + снимок; текущий
  каталог откладывается рядом как `….sp-before-restore-<ts>`), `require_mounts` / `require_paths` (смонтирован диск / каталог существует), `project` (имя compose-проекта, если оно не равно имени контейнера — как audio-streaming у jellyfin), `lock: qbittorrent` (закачки через WebUI API + `move-completed.sh`),
  `warning` / `rollback_warning` (тексты в диалогах), `health.checks` (http / tcp / dns), `danger` (пароль панели).
- **Сверка compose с контейнером:** `python3 -I deploy/docker/compare-inspect.py <контейнер> <compose.yaml>` (только чтение).
- **qBittorrent: торренты и обновление под замком.** «Остановить все / Запустить все» (страница «Торренты», карточка в «Обновлениях», быстрые действия)
  останавливают только ещё работающие торренты и запоминают их хеши в panel.db; «Запустить все» возобновляет только их (остановленные вами вручную не трогаются).
  «Остановить торренты и обновить…» (пароль панели): отказ при moving/checking*/move-completed.sh → остановка закачек, которые держат замок → обычное
  обновление через помощника (его замок не ослаблен) → возобновление только запомненных; при ошибке или откате они тоже возобновляются. Состояние
  (`qbt.updateFlow` в panel.db) восстанавливается после перезапуска панели. Код: `services/qbtUpdateFlow.ts`, `services/torrentControl.ts`, тесты — `qbtUpdateFlow.test.ts`.
- **Снаружи** все маршруты закрыты (`externalPolicy`), статус задач — в `INTERNAL_ONLY_READ`. Кнопки «обновить все» нет.
- Проверка без изменений: `sudo /usr/local/sbin/server-panel-docker update <имя> --dry-run`.

## Если что-то не так

| Симптом | Что проверить |
|---|---|
| Пустая страница | `journalctl -u server-panel -n 50`; убедиться, что `frontend/dist` собран |
| «нет данных» в разделе | всплывающая подсказка у «нет данных» показывает причину (нет прав, не задан секрет, сервис не отвечает) |
| «нет прав (sudoers)» | установленный sudoers или helper не совпадает с `deploy/` (см. `cmp` выше) |
| Docker «нет данных» | `docker ps --filter name=docker-socket-proxy` |
| Не пускает с правильным паролем | лимит 5 попыток за 15 мин с одного IP — подождать или войти с другого устройства |
